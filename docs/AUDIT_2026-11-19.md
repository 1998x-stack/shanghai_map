## 3. 分阶段修复

### P0：真实性与底图来源

1. 移除无证据人口硬编码，不根据“城市中心经纬度”断言行政中心地址。
2. OSM 改用唯一标准瓦片 URL `https://tile.openstreetmap.org/{z}/{x}/{y}.png`，明确版权署名；客户端默认浏览器缓存，不加离线下载、后台预抓取、禁用 Referer 或伪造请求头。
3. Leaflet 1.9.4 CSS/JS 增加官方 SRI；若 CDN 不可达，显示降级说明与官方地图链接。
4. 增加 Vercel 安全响应头，包含允许底图浏览器 Referer 的 `strict-origin-when-cross-origin`。不添加地理位置访问权限。

### P1：交互与移动体验

1. 使用 `zoomend moveend` 同步缩放、经纬度读数和缩放按钮边界，涵盖触控缩放、滚轮、键盘与按钮。
2. 将“返回参考中心”与“查看上海经纬度参考范围”作为两个清晰动作；参考范围是矩形外接边界，不代表行政界线。
3. 响应式布局：桌面左右结构、移动端地图优先并保留导航来源信息；底图版权署名不被悬浮控件遮挡。
4. 状态提示分为 loading/ready/warning/error；基于 `tileerror` 告知第三方服务不完整，而不是声称整个网站健康。

### P1：工程与验证

1. 增加零 npm 依赖的 Node 测试，覆盖真实瓦片 URL、缩放事件、参考范围、故障降级、复制坐标、静态来源、SRI 和部署响应头。
2. 增加本地 Python HTTP server + Node 只读路径冒烟，范围只有 `/`、`index.html`、`script.js`、`style.css`、`health.json`，**不会触发地图爬取**。
3. 增加 GitHub Actions 的 PR、主分支检验，以及静态 `/health.json` 产物指纹。其 `scope=static-build-only` 明确不验证第三方瓦片或真实浏览器交互。

## 5. 后续增强建议

- 真正运营中国境内公共地图服务时，首先完成地图审核、审图号、使用资质和数据授权的专业检查，再考虑替换为合法授权的天地图或商业地图底图，而不是“随便换 CDN”。
- 如果用上海 POI 搜索：引入逐点来源、坐标系标签、更新时间、可核实的官方地点信息；禁止将 GCJ-02 的值不做转换直接作为 WGS84 标记。
- 如需持续可用性监控，应只读检测**自身** `/health.json` 和服务响应；不要以自动监控模拟平移缩放给 OSM 瓦片服务器造成额外流量。
- 可以添加 Playwright 真机尺寸截图、键盘导航、复杂移动端触控验证，但应该使用受控浏览器测试环境与经许可的模拟瓦片服务，避免无意扫描 OSM 图块。

## 6. 风险结论

这是技术 Demo 的工程迭代，不能单靠 Vercel `READY`、OSM 开源数据许可或 CSS/JS 测试，将其认定为正式可商用地图产品。生产对外服务的地理信息合规审查属于**独立、尚未完成**的发布门槛。
